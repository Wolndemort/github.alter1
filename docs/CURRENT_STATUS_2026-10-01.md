# ALTER — текущий статус и следующий шаг

Дата проверки: 1 октября 2026 года.

Это актуальная короткая памятка. Старые аудиты могут содержать устаревшие цифры.

## Production

Проект готов к запуску без учёта ручной проверки оплат владельцем.

- Backend: полный набор — 573 теста пройдено.
- Web: 9 тестов и production build пройдены.
- Mobile: TypeScript и 18 тестов пройдены.
- Production `/health` и `/ready`: HTTP 200.
- Серверный commit совпадает с локальным и GitHub; точный hash проверяй командой ниже.
- Bot, nginx, PostgreSQL, Redis и media-worker работают.
- Luna используется основной моделью OpenRouter.
- Streaming получил увеличенный бюджет и timeout 30 секунд.
- Web сохраняет частичный ответ при обрыве потока.

## Безопасность и эксплуатация

- Redis ограничен 256 MB и работает с `noeviction`.
- Idempotency, rate limits, quota, concurrency и Redis-проверки проходят.
- Внешний контент считается недоверенным; русские prompt-injection фразы тоже распознаются.
- Docker-логи ограничены: 10 MB × 3 файла.
- Локальный backup проверен через restore drill на отдельной БД.
- Off-site backup ALTER подтверждён в Yandex Object Storage.
- Временный серверный файл с секретами `.env.audit-backup-` удалён.

## Проверенные функции

Web, mobile и Telegram имеют общий основной контур: диалог, streaming, память,
напоминания, check-in, документы, изображения, видео, аудио и голосовые ответы.
Документы создаются и редактируются в TXT, Markdown, JSON, CSV, RTF, PDF, DOCX,
XLSX, PPTX и ODT. В PPTX можно вставлять найденные изображения.

## Следующий этап: физический ALTER

Основной план находится в [ALTER_PHYSICAL_VOICE_PROTOTYPE.md](../ALTER_PHYSICAL_VOICE_PROTOTYPE.md).

Первый прототип не должен запускать всю модель локально. Raspberry Pi будет
устройством ввода/вывода, а ALTER API останется на VPS.

### Минимальный комплект

- Raspberry Pi 4 4 GB или Pi 5 8 GB.
- Надёжный блок питания, охлаждение и microSD 64 GB A2.
- USB-микрофон и USB-колонка.
- Одна физическая кнопка, Wi-Fi и HTTPS-доступ к API.

### Порядок работ

1. Подготовить Raspberry Pi OS и отдельного пользователя `alter-device`.
2. Установить клиент устройства как systemd-сервис.
3. Выдать отдельный ограниченный токен устройства; не использовать личный
   bearer-токен и не хранить API-ключи провайдеров на Pi.
4. Собрать цепочку: кнопка → запись голоса → ALTER API → ответ → озвучивание.
5. Добавить световой индикатор: слушает, отправляет, отвечает, ошибка.
6. Добавить offline-очередь и повтор запроса только с idempotency key.
7. После стабильного голосового прототипа подключать ESP32, NFC и механику.

### Критерий готовности первого устройства

Устройство должно 20 раз подряд выполнить короткий диалог, показать ошибку при
отсутствии сети, не раскрыть токен в логах и восстановиться после перезапуска
питания. Только после этого добавлять камеру и механику.
